# Spec Delta

## Purpose

Plans the ad shot by shot and previews every shot as a cheap still image the user can edit and approve; the approved images are the actual first frames of the video clips, so the preview is the start of the final ad.

## ADDED Requirements

### Requirement: Draft storyboard
From a project's script, brand, product, actor and brief, the system SHALL draft a storyboard with the user's language model. Each shot SHALL have: purpose (hook, problem, demo, proof, offer, call to action, or other), shot type (talking, product in hand, cutaway, or real product), framing and camera, setting, action, spoken line (possibly empty), on-screen text (possibly empty), and duration in seconds. The sum of shot durations SHALL be within 15% of the target length, and every word of the script SHALL be assigned to exactly one shot in order.

#### Scenario: Script fully covered
- **WHEN** a storyboard is drafted from a 75-word script
- **THEN** concatenating the shots' spoken lines in order reproduces the script exactly

#### Scenario: Durations match target
- **WHEN** the target length is 30 seconds
- **THEN** the drafted shot durations add up to between 25.5 and 34.5 seconds

### Requirement: Preview frames
For each shot except real-product shots, the system SHALL generate one preview frame with the chosen image-edit model, using the actor's references, the product's primary photo and the shot's framing, setting and action, at the project's aspect ratio. Real-product shots SHALL preview using the product cutout locally at no cost. Each generated frame SHALL be drift-checked (see product-fidelity) when the shot shows the product.

#### Scenario: Frames generated
- **WHEN** a user generates frames for a six-shot storyboard with one real-product shot
- **THEN** five frames are generated by the image model, the real-product shot is rendered locally, and the cost of the five frames is shown before starting

#### Scenario: Frame drift flagged
- **WHEN** the drift check finds the label text in a frame does not match the product
- **THEN** the shot is marked with the issue and offers "Regenerate frame" and "Use real product shot"

### Requirement: Edit and approve storyboard
Users SHALL be able to edit any shot field, reorder, add, duplicate and delete shots, regenerate a single frame (optionally with extra instructions), replace a frame with an uploaded image, and change the actor for the whole storyboard. A shot SHALL be approved individually or all at once; editing an approved shot's visual fields SHALL return it to unapproved. Clip generation SHALL only run for approved shots.

#### Scenario: Regenerate one frame
- **WHEN** a user regenerates the frame of shot 2 with the note "hold the bottle closer to camera"
- **THEN** only shot 2 gets a new frame, the previous frame is kept in its history, and the user can switch back to it

#### Scenario: Editing un-approves
- **WHEN** a user changes the framing of an approved shot
- **THEN** the shot becomes unapproved and its frame is marked out of date

#### Scenario: Line-only edits keep the frame
- **WHEN** a user changes only the spoken line of a shot
- **THEN** the frame is kept and the shot stays approved

### Requirement: Frames become clip inputs
When a shot is generated as video, its approved frame SHALL be passed to the video model as the first frame. Users SHALL be able to set an optional end frame per shot (generated, uploaded, or the next shot's frame), which SHALL be passed as the last frame to models that support it.

#### Scenario: First frame used
- **WHEN** an approved shot is rendered with an image-to-video model
- **THEN** the request's first-frame input is the shot's approved frame image, and the clip's first frame visually matches it

#### Scenario: End frame unsupported
- **WHEN** a shot has an end frame and the chosen video model has no last-frame input
- **THEN** the user is told the end frame will be ignored for that model before rendering

### Requirement: Multi-shot blocks
Users SHALL be able to group consecutive shots into a block (up to the model's maximum duration) to be generated as one clip on models that support multi-shot prompts. The block SHALL use the first shot's frame as its first frame and describe each shot in order in the prompt.

#### Scenario: Two-shot block
- **WHEN** a user groups a 4-second selfie shot and a 4-second close-up into one block on a model that supports multi-shot prompts and 8-second clips
- **THEN** one 8-second clip is generated containing both shots, and the storyboard shows them as one block
